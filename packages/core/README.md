# @vitana/core

VTID-05183 (Native app Wave 1, N1; program `docs/programs/native-app/NATIVE-APP-PLAN.md` §3 "Extraction is
phased", steps 1–2). The layer through which the native app (`apps/mobile`) reaches web code. It is **not** an npm
workspace: `apps/mobile/resolution.js` maps `@vitana/core/*` to `packages/core/src/*` (Metro, Jest and `tsconfig`
`paths` share that one table), and every third-party import resolves from `apps/mobile/node_modules`.

## What is in it

| Kind | Files | Rule |
|---|---|---|
| **Re-exports** | `src/<area>.ts` with `export … from '@/…'` | only transitively class-A web modules; each listed in `manifest.json` with its reason and consumer lanes |
| **Extracted declarations** | `src/extracted/*.generated.ts` | copied verbatim from the web source by `scripts/native/gen-core-extract.mjs` (driven by `extract.json`); never edited |
| **Config-only clients** | `src/config.ts`, `src/gateway.ts`, `src/supabase.ts`, `src/storage.ts`, `src/active-org.ts` | every endpoint and the storage are injected; **no default anywhere** |

Subpath imports only (no barrel: Metro does not tree-shake):
`config`, `gateway`, `supabase`, `storage`, `database`, `data-routing`, `registry`, `orb-navigation`, `permissions`,
`roles`, `business-mode`, `nav`, `tenants`, `language`, `types`.

The clients take their endpoints from `endpoints(config)` in `apps/mobile/src/config/env.ts`, the single place that
refuses production and staging hosts and the production publishable key. Never build a client from a literal URL.

## Gates

```bash
node scripts/native/gen-core-extract.mjs            # regenerate src/extracted/ after a web source change
node scripts/native/core-closure.mjs --write        # closure.generated.json + scripts/native/mobile-ci-paths.generated.json
node scripts/native/gen-core-extract.mjs --check    # NATIVE-CI: fails on drift
node scripts/native/core-closure.mjs --check        # NATIVE-CI: class A only, manifest, no production host, fresh outputs
node scripts/native/core-closure.mjs --md           # refresh the module map below (a snapshot, not checked)
```

`closure.generated.json` lists every `src/` file core reaches; the native resolver admits those (plus the Wave 0 i18n
shards) and throws for anything else under `src/`. The web Supabase client and gateway base fall back to production
and are never in it.

A lane that needs another web module asks for a one-line manifest PR (and a re-export). A transitively class-B/C
module cannot be re-exported: it needs a move package.

## Move order (program step 3 — each its own sparred package, gated by the web build, Vitest, the registry tests and a staging suite)

1. Inject configuration and storage into `src/integrations/supabase/client.ts` and `src/lib/gateway-base.ts` behind
   the existing exports, with no web behaviour change. 1074 modules have the web Supabase client in their runtime
   closure and 880 the gateway base; 45 modules (28 hooks, 16 `src/lib`, 1 service) are own-class A and blocked only
   by those two singletons.
2. Split `src/lib/i18n-toast.ts` into a portable `t()` and the `sonner` `notify()` (unblocks
   `src/lib/locale-format.ts` and 32 others).
3. Split icons out of `business-mode.ts`, `drawer-nav.config.ts`, `MobileBottomNav.tsx` and `role-navigation.ts` into
   data files the web imports; each replaces an `extract.json` entry, and core re-exports the moved module instead.
4. The realtime router's configuration (`src/integrations/supabase/realtime.ts`, `VITE_REALTIME_URL`).
5. `src/lib/query-persist.ts` storage.

Also not in core today: `src/i18n/index.ts` (`import.meta.glob`; the native loader is `apps/mobile/src/i18n`), zod
schemas (only two class-C files import zod) and query keys (local to each hook, no central module), and the zustand
stores `newsFeedPreferencesStore`/`userInterestsStore` (`persist()` without `storage` defaults to `localStorage`:
the analysis' `implicit-storage` signal).
